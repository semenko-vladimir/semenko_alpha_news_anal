# Ядро анализа

Приложение подключает `AnalysisPipeline` в mvp_offline и agentic_fixture. Ядро использует внедряемые интерфейсы модели и инструментов поиска. Fake-клиент проверяет интеграцию; качество реальной модели требует отдельной оценки. Промышленная эксплуатация не подтверждена.

Из корня выполните `python -m unittest backend.test_analysis_pipeline -v`. Тесты используют синтетические данные и fake-клиенты. Ядро считает ответ модели недоверенными структурированными данными, проверяет ссылки, экспозицию и атрибуцию банка. При ошибке валидации оно допускает одну коррекцию. Инструкции внутри источника не исполняются.

`validated` означает проверку структуры и происхождения. Проверяющий человек оценивает истинность, поддержку тезиса текстом и актуальность позиции банка. Для observed_fact нужна ссылка на существующее свидетельство, для bank_position банковский источник с ISO-датой. Подтверждённая экспозиция требует evidence с `confirmed_exposure` от доверенного upstream adapter; ядро не проверяет правдивость этого флага и его company scope по тексту. Совпадения ключевых слов не доказывают экспозицию.

Ядро принимает CFO/COO. Пустые ID/тексты, повторные evidence IDs и конфликтующие kind/date одного source ID дают ошибку. Несколько фрагментов одного источника допустимы при согласованной metadata. Upstream согласует пропущенную и заполненную metadata, прежде чем передавать их вместе.

Лимиты: claim 3000 символов, 24 ссылки, сериализованный JSON 12000 символов с `ensure_ascii=False`. Проверка уже возвращённого объекта не ограничивает память произвольного внедрённого transport. Отмена кооперативная: ядро останавливается после возврата tool/model и перед каждым вызовом модели, включая correction; блокирующий внедрённый вызов оно не прерывает.
