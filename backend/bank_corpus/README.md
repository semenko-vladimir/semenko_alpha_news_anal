# Локальный поиск банковских документов

Пакет использует стандартную библиотеку Python и SQLite с FTS5. Индекс хранит текст документов. Оператор размещает его в локальной папке `data/processed/`, исключённой из Git, и не включает в образ. При импорте пакет не читает файлы, не создаёт их и не обращается к модели или сети.

Из корня репозитория:

```powershell
python -B -m unittest discover -s backend -p test_bank_corpus.py -v
```

Операторский build (из `backend`, все четыре пути обязательны):

```powershell
python -B -m bank_corpus --index ../data/processed/bank/index.sqlite3 --manifest ../local/bank-manifest.json --ocr-dir ../data/processed/analytics --pdf-dir ../data/raw/analytics
```

Пример интеграции из backend:

```python
from bank_corpus import BankRepository
repo = BankRepository(operator_configured_index_path)
passages = repo.search("инфляц бензин", limit=3)
result = repo.search_with_status("инфляц бензин", limit=3)
```

`BankRepository(index_path)` принимает путь, который задаёт оператор. Не брать его из job, новости или пользовательского запроса. `search` возвращает список словарей с обязательными `source_id/document_date/locator/text/historical/quality` и дополнительными `document_id/title/page/source_kind/synthetic/rank/corpus_version`. Source ID относится к документу и версии корпуса, locator указывает PDF-страницу, начиная с 1. Несколько фрагментов могут ссылаться на один источник с разными locators. При сортировке меньшее значение SQLite BM25 (`rank`) идёт первым, затем идут дата по убыванию и `document_id/page`. Версия SHA-256 охватывает манифест, текстовые файлы и PDF.

`search_with_status` возвращает `{status, passages}`: отсутствующий индекс `not_checked`, пустой поиск `not_found`, только исторические попадания `historical`, наличие датированного неисторического материала `found`. Это наличие позиции **на дату документа**, не подтверждение её актуальности сегодня и не подтверждение связи с компанией. В смешанной выдаче историчность проверять у каждого passage; исторический текст нельзя отображать текущей позицией. Неизвестная дата никогда не попадает в датированную выдачу. Поломанный индекс/неподдерживаемая схема — `CorpusError`, не ложный `not_found`.

Запрос ограничен 256 символами и 12 словами, `limit` принимает значения от 1 до 10. Поиск использует слова как текст и объединяет их через OR с префиксным совпадением; входные FTS-операторы не исполняет. Для русских окончаний можно передавать основу слова: `инфляц`. Морфологического поиска и семантического ранжирования нет. SQL-запросы используют параметры. Фрагмент выдачи содержит до 600 символов и предназначен для локального интерфейса. Для передачи текста внешней модели требуется отдельное разрешение. FTS не проверяет смысл, числа, инструкции внутри документа или релевантность компании.

`build_index(index_path, *, manifest_path, ocr_dir, pdf_dir)` атомарно строит индекс. Каждый manifest document содержит document_id/title/document_date/pages/ocr_file/pdf_file/historical/synthetic/quality/date_basis. Дата только exact ISO или null, без угадывания месяца/имени файла. Для real-материала требуется существующий PDF и `date_basis=verified_pdf` при известной дате; это аттестация оператора, не автоматическая визуальная сверка PDF. Для synthetic fixtures PDF не требуется, source_kind остаётся synthetic. Маркеры `## Страница N` должны идти строго от 1 до pages. Старые материалы до 2026 автоматически historical в рамках этого frozen кейса; флаг historical можно задать и более новым документам. Порог относится только к этому корпусу, не является общей политикой свежести.

Оператор хранит manifest отдельно от репозитория и указывает в нём собственные текстовые материалы. Перед использованием сверьте текст и числа с исходными документами. Выдача сохраняет отметку качества; таблицы и графики требуют проверки. При отсутствии материалов система не подставляет синтетические данные.
