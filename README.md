# Альфа Хак: персонализированная бизнес-аналитика

Проект хакатона Альфа-Банка для руководителей компаний с выручкой свыше 15 млрд рублей. Руководитель выбирает компанию и роль CFO или COO, запускает анализ внешних событий, изучает риски и возможности и проверяет источники каждого вывода. В карточке он уточняет связь события с бизнесом и задаёт вопрос.

В целевой версии банковские системы передают контекст компании с учётом прав доступа. Руководитель уточняет профиль и добавляет недостающие сведения. Сервис сопоставляет их с внешними новостями и аналитикой банка.

В прототипе есть 11 публичных компаний из разных секторов, финансовые показатели с периодами и источниками, обновляемые официальные новости. Оператор может подключить четыре обезличенных профиля кейса и индекс банковских документов. Интеграция с банковскими системами и банковская авторизация пока отсутствуют. Неизвестные единицы и связи остаются неизвестными; порог выручки применяется только к сопоставимому годовому показателю в рублях.

## Первый запуск финальной сборки

Нужны Python 3.14 с SQLite FTS5 и Docker Compose v2. Из корня проекта (PowerShell):

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r deploy/runtime-requirements.lock
.venv/Scripts/python.exe -B scripts/prepare_product.py --output .tmp/product-demo --port 8089
docker compose -p alpha-product --env-file .tmp/product-demo/product.env -f compose.product.yaml up --build -d --wait
```

Откройте http://127.0.0.1:8089/. Публичные профили доступны сразу, новости загружаются при старте и затем раз в час. В этом воспроизводимом запуске анализ выполняет явная тестовая модель; живой брокер подключается отдельно и никогда не заменяется fake при ошибке. Все контейнеры привязаны к loopback.

[Полная инструкция финальной сборки](docs/final-product.md) включает приватные профили, живую LLM, закрытый HTTPS-вход, источники финансовых показателей и репетицию сдачи. В Linux/macOS используйте `.venv/bin/python`.

[Локальный режим Ollama](docs/local-llm.md) остаётся экспериментальным. Его модели не входят в разрешённый список кейса. В документации сохранены результаты восьми генераций основного пилота и двух ранних проб.

**Готовность частичная.** В облачном пилоте ответ CFO прошёл проверку формата, но не проверку финансового обоснования. Ответ COO оборвался внутри JSON, и приложение его отклонило. Новые облачные вызовы остановлены; исходные ответы сохранены. [Результаты и ограничения пилота](docs/testing.md) описывают, что проверено и что ещё предстоит оценить.

[Материалы для защиты](docs/release/FINAL-AUTONOMY-026-A/submission.md) описывают текущие результаты и открытые требования. Банковский IAM, домен, доступ жюри и ценность на живых новых событиях пока не подтверждены.

## Синтетический инженерный пример

Нужны Python 3.14 с SQLite FTS5 и Docker Compose v2. Выполните команды из корня проекта (PowerShell):

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r deploy/runtime-requirements.lock
.venv/Scripts/python.exe -B scripts/prepare_mvp_demo.py --output .tmp/mvp-synthetic --port 8087
docker compose --env-file .tmp/mvp-synthetic/compose.env config
docker compose --env-file .tmp/mvp-synthetic/compose.env up --build -d
```

Откройте http://127.0.0.1:8087/. Выберите компанию, CFO или COO, нажмите кнопку анализа и откройте карточку. Проверьте источники, неизвестные сведения и уточнение. Модель fake: этот пример проверяет работу приложения, а качество генерации реальной LLM требует отдельной оценки. Генератор не читает предоставленные организаторами материалы и откажется перезаписать существующую папку.

Для остановки выполните `docker compose --env-file .tmp/mvp-synthetic/compose.env down`. В Linux/macOS используйте `.venv/bin/python` вместо `.venv/Scripts/python.exe`. Установка зависимостей и сборка образов требуют доступа к реестрам пакетов.
