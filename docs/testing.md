# Проверки

Проверяйте отдельно работу приложения, качество вывода модели и условия сдачи. Успешная сборка и HTTP-тесты подтверждают инженерный путь; эксперт оценивает обоснованность и пользу рекомендаций.

## Финальная сборка на реальных источниках

Последний завершённый чистый прогон до текущей редактуры включал 221 backend-тест, 7 evaluation, 3 stabilization, 42 frontend-теста и сборку. Он прошёл из новой распаковки кандидата с закреплёнными зависимостями. Docker api/web стали healthy; 22 пары «компания × роль» прошли HTTP-путь, Chrome проверил ширины 1440/390/320. После stop/start сохранились 28 новостей и карточка. Четыре ошибки официальных источников оставались видимыми. Режим был `mvp_offline` / `FAKE MODEL`, без подставных ответов API и вызовов реальной LLM.

Для изменённой версии нужен новый архив и связанные проверки. Сравнивайте SHA исходников с manifest; старые числа не подтверждают новые байты. `compose config` проверяет конфигурацию, но не сборку и запуск.

## Облачный пилот и ограничения качества

| Вариант | Проверка формата | Содержательный результат |
| --- | --- | --- |
| CFO | Exact5/schema VALIDATED; 366 выходных токенов, 4.882 с | Не указана зависимость оплаты от приёмки как условие финансового эффекта; смысловой критерий 3 не пройден |
| COO | Ответ с Markdown оборвался внутри JSON на 512 выходных токенах; приложение отклонило его | Принятого ответа нет |

Всего в этом пилоте было 2 API-вызова и 2465 токенов. Рублёвый расход неизвестен. После ошибки контроллер остановил облачную генерацию для обоих этапов; третью попытку не отправляли. Исходные ответы сохранены без исправления. Повтор под новым ID запрещён. Полезность пары CFO/COO, живого диалога и банковского контекста ещё не подтверждена.

Исторические измерения локальных моделей и их ограничения описаны [отдельно](local-llm.md): восемь генераций основного пилота и две ранние пробы. Независимая проверка выполнила 23 проверки без генерации, подтвердила карантин небезопасного CFO-ответа и отсутствие локальных ID в разрешённом списке кейса. Это не новые inference-вызовы и не приёмка финансового качества.

Предыдущий FINAL-PRODUCT-001 проверял 203 backend- и 38 frontend-тестов, отдельные evaluation/stabilization 7 и 3, native HTTP для 15 компаний и двух ролей, 66 Chrome-сценариев, Docker, приватный Unix-сокет и HTTPS/Basic Auth. Поздний локальный этап включал 219/41 тест. Эти результаты относятся к прежним версиям. Проверки с синтетическими credentials подтвердили отказ GET/POST без входа и отсутствие операции; они не доказывают банковский IAM.

Для обычной упаковки предусмотрен `python scripts/package_product.py --output .tmp/release/alpha-product.zip`. Скрипт собирает явный публичный состав, добавляет SHA-манифест и отказывается перезаписать архив. Исходные CSV/PDF/SQLite и credentials исключены. Распакуйте комплект в новую папку и повторите запуск из README. LIVE требует отдельного назначения и доступной квоты: до трёх попыток из четырёх, одна в резерве; при quota/auth/unknown/invalid — остановка. Текущий cloud stop остаётся в силе.

Установите зависимости по [инструкции](setup.md). Из корня в PowerShell:

```powershell
.venv/Scripts/python.exe -B -m unittest discover -s backend -q
.venv/Scripts/python.exe -B scripts/verify-agent-chain.py
.venv/Scripts/python.exe -B scripts/verify-local-demo.py
.venv/Scripts/python.exe -B -m unittest discover -s tests/evaluation -q
.venv/Scripts/python.exe -B -m unittest discover -s tests/stabilization -q
npm --prefix frontend run typecheck
npm --prefix frontend run test:lifecycle
npm --prefix frontend run test:render
node --test frontend/tests/e2e-posts.test.cjs
npm --prefix frontend run build
```

Backend-тесты используют synthetic fixtures и fake transport. HTTP smoke запускает собственный loopback-сервер с отдельной SQLite и проверяет доступ, четыре company/role контекста, источники и идемпотентность. Успех этих проверок не доказывает качество LLM или наличие банковского подключения. Артефакты тестов сохраняются в `.tmp/`.

## Интеграция с локальными материалами и браузер

`scripts/verify-mvp.py --offline` запускает расширенный набор, включая банковское покрытие и браузер. Он требует три CSV в `data/raw/clients/` с именами `df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv`, `df_Fid_Uid_link_hack.csv`, новостную БД `data/processed/news/news.sqlite3` и банковский индекс `data/processed/bank/index.sqlite3`. Assertions этого набора ожидают реальные локальные материалы. Синтетический quickstart не создаёт такой индекс. Проверка банковского покрытия требует соответствующего локального корпуса; из публичного клона она недоступна без этих материалов. Переносимые backend-тесты и HTTP smoke выше проверяют схемы и ошибки без него.

`npm --prefix frontend run test:e2e` также требует свежую сборку, входные файлы и банковский индекс. Установите Playwright-core отдельно в своё QA-окружение; задайте `ALPHA_PLAYWRIGHT_MODULE` абсолютным путём к модулю, `ALPHA_CHROME_PATH` путём к Chrome и `ALPHA_TEST_PYTHON` путём к Python с backend-зависимостями. Тест запускает собственные серверы на свободных портах, сравнивает хеши входов и закрывает свои процессы. Chrome работает с sandbox. Внешние запросы блокируются. Положительные сценарии используют API без mocks; ошибки интерфейса проверяются отдельными mocks.

## Метрики и оценка

[Синтетические наборы](../examples/README.md) содержат cases и labels для инженерной проверки. Проверяйте поддержку выводов источниками, атрибуцию банка, различие темы и экспозиции, полезность для роли, задержку, usage и долю остановок. Авторские labels и структурная валидация не заменяют человеческую оценку полезности.

Для повторяемого ручного показа synthetic Docker сценария и CLI новостей используйте [маршрут жюри](judging.md). Критерии периодического мониторинга, human review и безопасного расширения — в [quality monitoring](quality-monitoring.md).

При изменении контекста или версии политики проверяйте регрессию cache fingerprint: тот же запрос после смены policy должен создать новый результат, а старые карточки/snapshots остаться pinned; повтор запроса в новой версии сохраняет идемпотентность. Для оговорок проверяйте, что краткие категории не теряют исходные строки и provenance, включая неизвестные коды. Качество реальных LLM на новых событиях не подтверждено; стоимость gateway требует отдельного исследования. Для Docker smoke нужен работающий daemon; `compose config` подтверждает только конфигурацию.
