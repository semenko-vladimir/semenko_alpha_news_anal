# Бизнес-инсайты: материалы для защиты

Материалы к защите, 26 октября 2026. Прототип прошёл инженерные проверки; экспертная оценка полезности и часть требований кейса остаются открытыми. Результаты проверок относятся к конкретной версии архива; её SHA256 указан рядом с ZIP. Публикации не было.

Продукт связывает новости с контекстом компании и ролью руководителя, предлагает условный сценарий риска/возможности и конкретную следующую проверку. Пользователь выбирает компанию и CFO/COO, открывает анализ, источники, оговорки и этапы подготовки, задаёт уточнение. Бизнес-решение от имени клиента не исполняется.

Откройте [презентацию](presentation.html), [PDF](presentation.pdf), [сценарий показа](demo-script.md), [матрицу требований](requirements-matrix.md) и [ответы для защиты](defense-qa.md). Снимок интерфейса показывает реальные публичные данные с явно тестовой FAKE-моделью; это не образец качества живой LLM.

## Воспроизведение без расходования LLM-квоты

Распакуйте проверенный исходный архив в новую папку. Выполняйте команды из его корня. Требуются Python 3.14, Docker/Compose v2 и сеть для первой сборки и официальных источников. Ниже используется отдельный проект и свободный loopback-порт; это **mvp_offline / FAKE**, никаких API-ключей.

```powershell
python -B scripts/prepare_product.py --output .tmp/judging-public --port 8093
docker compose -p alpha-judging-public --env-file .tmp/judging-public/product.env -f compose.product.yaml up --build -d --wait
docker compose -p alpha-judging-public --env-file .tmp/judging-public/product.env -f compose.product.yaml ps
```

Откройте `http://127.0.0.1:8093/`. Дождитесь завершения первого обновления источников, выберите FESCO и роль, запустите анализ. При изменении входных новостей прежний idempotency key не переиспользуйте как новый запрос; UI управляет ключами. Ошибки внешних источников видимы и не подменяются заглушками. После проверки:

```powershell
docker compose -p alpha-judging-public --env-file .tmp/judging-public/product.env -f compose.product.yaml down
```

Не добавляйте `-v`, если runtime должен сохраниться. Живой брокер подключается по [инструкции](../../final-product.md) и отдельному назначению. [Локальная модель](../../local-llm.md) доступна как эксперимент без Docker, только с публичными данными; её ID не входят в разрешённый список кейса. Автоматического переключения на неё нет.

## Фактическая готовность и открытые критерии

Исторические проверки прежнего кандидата: 219 backend-тестов, 41 frontend-тест и сборка; из прежнего чистого архива повторно 219 backend-тестов, Docker api/web healthy, 22 HTTP-сценария, Chrome 1440/390/320 без ошибок/overflow. Они описывают прежние байты и техническое поведение; полезность рекомендаций ими не измеряли.

Текущая готовность: **partial**. В новом облачном пилоте production-проверка exact5/schema дала CFO статус VALIDATED: 366 completion-токенов, 4.882 с. Строгая семантическая рубрика дала FAIL по пункту 3: модель не назвала зависимость оплаты от приёмки условием финансового эффекта. Ответ COO с markdown-разметкой достиг 512 токенов и оборвался внутри JSON; parser отклонил его. Контроллер остановил cloud-вызовы для stage1 и stage2; третью попытку не отправляли. Всего 2 API-вызова, 2465 токенов; рублёвый расход неизвестен. Исходные ответы сохранены без исправления, повторы запрещены. Различие пары ролей, живой диалог, влияние банковской аналитики и устойчивость остаются непроверенными.

Локальные измерения относятся к истории: восемь генераций основного пилота и две более ранние пробы (8+2). В stage1 новых локальных inference не было. Независимый review выполнил 23 offline-проверки, подтвердил карантин CFO и отсутствие локальных ID в разрешённом списке кейса (PDF, стр. 12). Это не новая генерация и не приёмка полезности.

До окончательной сдачи остаются: независимая экспертная оценка полезности, GATE на разрешённом модельном маршруте и новых событиях после разбора stop, публикация проверенной версии в GitHub с точным commit/tag. Публичный репозиторий сейчас содержит прежний initial commit `ae19e2a678421bc49224b6777ce0810b1f62fb28`, который **не является этим кандидатом**. Имя `alfa-hack-2026` в требованиях — аккаунт жюри для доступа к приватному репозиторию, а не обязательное имя тега. Внешний демонстрационный сервер рекомендован условиями, его доступность для жюри ещё не подтверждена. Интеграция с настоящей авторизацией/домашней страницей Альфа-Бизнеса пока моделируется отдельным прототипом.

Публикация, выдача доступа, коммиты и staging в рамках этой подготовки не выполнялись.
