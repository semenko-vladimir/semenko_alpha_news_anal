# Демонстрационный маршрут

Для сдаваемой сборки с реальными компаниями используйте [финальный маршрут и закрытый запуск](final-product.md#репетиция-перед-сдачей). Ниже описан отдельный сценарий на синтетических данных с явной тестовой моделью.

Этот сценарий проверяет переносимый синтетический прототип. Он не включает реальную LLM, банковский индекс, банковскую авторизацию, публикацию или доступ жюри. Синтетическая fake-модель проверяет связность интерфейса и сохранение происхождения; полезность ответов модели остаётся **not_checked**. LIVE CBR refresh ниже — необязательная операция источника, не вызов LLM.

## Запуск Docker

Из корня репозитория в PowerShell. Требуются Docker Compose v2, Python 3.14 и доступ к registry для первой сборки. Все команды используют отдельное имя проекта; замените суффикс при повторном запуске, если прежний стек ещё нужен.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r deploy/runtime-requirements.lock
.venv/Scripts/python.exe -B scripts/prepare_mvp_demo.py --output .tmp/mvp-synthetic --port 8087
$envFile = (Resolve-Path .tmp/mvp-synthetic/compose.env).Path
docker compose -p alpha-judge-20261025 --env-file $envFile config
docker compose -p alpha-judge-20261025 --env-file $envFile up --build -d
docker compose -p alpha-judge-20261025 --env-file $envFile ps
```

В `ps` оба сервиса должны стать healthy. Откройте `http://127.0.0.1:8087/`. Выберите одну из вымышленных компаний и роль CFO, запустите анализ; затем смените на COO и запустите снова. Проверьте, что контекст роли/признаков указан в карточке, а сами новости остаются теми же исходными событиями. Так можно проверить изменение контекста роли. Для оценки бизнес-пользы нужны реальные ответы и экспертная проверка.

Откройте карточку и проверьте дату и ссылки на источники, разделение факта/сценария и видимый статус позиции банка. Раздел «Что важно проверить» кратко показывает бизнес-категории существенных оговорок; раскройте с клавиатуры «Показать исходные оговорки и ограничения», чтобы увидеть исходные записи и их происхождение. Полные исходные оговорки и их происхождение доступны в раскрывающемся блоке. Сводка карточки формируется из принятого AI-вывода; в fake-режиме он явно помечен `FAKE MODEL`. Синтетический пример не подключает банковский индекс: позиция банка должна явно отсутствовать, а не выглядеть как банковское подтверждение. Используйте предложенное уточнение или задайте вопрос в диалоге; пользовательский ответ не становится подтверждённым фактом автоматически.

## Trace и новости

Сначала раскройте в карточке анализа раздел «Как подготовлен анализ»: интерфейс показывает стадии и доступные причины/источники trace. HTTP/Network inspector браузера — дополнительная техническая проверка. В запросе `POST /api/v1/companies/{company_id}/analysis-runs` найдите `run_id`; trace endpoint read-only, сохраняет проверки доступа запуска и возвращает только `run_id`, `company_id`, `role_id`, `status`, `execution_mode`, `trace` и `features`. В `trace` ожидаются безопасные стадии/статусы, без prompt, текста клиента и скрытых рассуждений. Для тестового локального доступа endpoint можно запросить из PowerShell:

```powershell
$runId = '<run_id из ответа POST>'
Invoke-RestMethod "http://127.0.0.1:8087/api/v1/analysis-runs/$runId/trace"
```

Если `execution_mode` показывает offline/fake, это ожидаемо; не трактуйте trace как доказательство реальной генерации.

Проверить состояние news DB внутри работающего API контейнера можно без сети:

```powershell
docker compose -p alpha-judge-20261025 --env-file $envFile exec -T api python -m backend.news_service status --database /var/lib/alpha-news/news.sqlite3
```

В Compose CLI обращается к рабочей копии базы `/var/lib/alpha-news/news.sqlite3`, не к исходной базе на хосте. Статус показывает отдельно время последнего успешного получения и возраст публикаций: успешное получение не гарантирует свежие даты статей. Необязательное обновление делает один ограниченный запрос к RSS ЦБ и может обратиться к сети:

```powershell
docker compose -p alpha-judge-20261025 --env-file $envFile exec -T api python -m backend.news_service refresh --database /var/lib/alpha-news/news.sqlite3
docker compose -p alpha-judge-20261025 --env-file $envFile exec -T api python -m backend.news_service status --database /var/lib/alpha-news/news.sqlite3
```

После добавления записей новый анализ использует обновлённую рабочую базу без перезапуска. При каждом старте entrypoint заново копирует `MVP_NEWS_DB_FILE` в runtime volume, поэтому ручные изменения после refresh теряются при перезапуске, если оператор отдельно не обновил исходную базу. Для обычного воспроизводимого показа достаточно `status` без сетевого запроса; refresh пропустите, если сетевой вызов не нужен.

Остановка удаляет контейнеры этого отдельного Compose-проекта, сохраняя volumes:

```powershell
docker compose -p alpha-judge-20261025 --env-file $envFile down
```

Не добавляйте `-v`. Не назначайте жюри доступ к локальным данным. Условие `alfa-hack-2026` применимо только если координатор отдельно публикует приватный GitHub-репозиторий; этот сценарий ничего не публикует и не меняет права.

## Запуск без Docker

После зависимостей, сборки frontend и генерации синтетики по [инструкции настройки](setup.md), запустите:

```powershell
.venv/Scripts/python.exe -B scripts/run_mvp.py
```

Интерфейс будет на `http://127.0.0.1:8010/`. Здесь `run_mvp.py` копирует исходную базу в отдельный рабочий каталог `.tmp/mvp-local/`; news CLI должен указывать на рабочую копию, а не на исходную базу:

```powershell
.venv/Scripts/python.exe -m backend.news_service status --database .tmp/mvp-local/news.sqlite3
# Только если оператор хочет выполнить один внешний CBR RSS fetch:
.venv/Scripts/python.exe -m backend.news_service refresh --database .tmp/mvp-local/news.sqlite3
```

Остановите локальный сервер через Ctrl+C. Дополнительные команды сборки и ограничения см. в [setup](setup.md) и [testing](testing.md).
