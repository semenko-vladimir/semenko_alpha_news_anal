# Локальная модель сервера

Оператор может включить отдельный режим `local_ollama`. Он использует уже установленную модель Ollama через loopback или частный SSH-туннель. Ключ и подписка внешнего LLM API этому маршруту не нужны; расход ресурсов сервера остаётся. Основной `broker_live`, его шесть ID, endpoint, квота4 и cap512 сохранены. Автоматического переключения между провайдерами нет.

Это экспериментальная альтернатива. Установленные локальные ID отличаются от разрешённого списка кейса; работоспособность локального запуска не подтверждает его допустимость для сдачи хакатона. Полный перенос финансового анализа на эту модель пока не принят.

## Что реализовано

```mermaid
flowchart LR
    A[Публичный профиль и новость] --> B[Планирование и отбор]
    B --> C[Устойчивая операция SQLite]
    C --> D[Компактный контекст и ссылки e0/e1]
    D --> E[Ollama на сервере]
    E --> F[Сценарий / проверка / статус банка]
    F --> G[Восстановление source ID и общий валидатор]
    G --> H[Карточка с источниками или явная остановка]
```

Режим обслуживает только 11 публичных компаний. Профили кейса, платежи, физические лица и банковский индекс ему не передаются; несовместимая конфигурация отклоняется до загрузки частных входов. HTTP-клиент не выбирает модель или URL. Адаптер допускает только назначенные теги и loopback-адрес 127.0.0.1, блокирует redirect и отключает proxy из окружения для этих запросов.

Короткие обозначения источников обратимо преобразуются в исходные ID на сервере приложения; даты остаются отдельными полями. Структурированный формат v2 требует поля сценария, конкретной проверки, источников и экспозиции. Статус отсутствия банковского материала фиксируется по составу входов и не является банковской позицией. Поля сценария/проверки за модель не дописываются. После преобразования применяется прежняя проверка бизнес-утверждений и происхождения.

Перед отправкой запроса приложение сохраняет операцию и fingerprint входа. Завершённый результат читается из истории; при неизвестном исходе повтор запрещён. Один локальный запрос выполняется одновременно; на invalid/unknown дальнейшие генерации останавливаются. Дневной бюджет брокера к локальной модели не приписывается. Интерфейс показывает фактического провайдера и модель, экспериментальный статус и причину остановки.

## Измерения серверного пилота

Локальные измерения относятся к истории: восемь генераций основного пилота и две более ранние пробы (8+2). После пилота новых локальных генераций не было. Независимый ревьюер выполнил 23 проверки без генерации, подтвердил карантин CFO и отсутствие локальных ID в разрешённом списке кейса (PDF, стр. 12). Это не новая генерация и не приёмка полезности.

26 октября 2026: Ollama 0.34.4, 14.4 ГБ RAM, 8 логических CPU, GTX 1050 с 2 ГБ VRAM. Пилот выполнялся на CPU с четырьмя потоками: GPU 0, context 4096, output <= 512, think:false, keep_alive 0. Веса не скачивались, службы не перезапускались. Выполнено восемь локальных генераций без запросов к облачному шлюзу.

| Модель/вход | CFO | COO | Результат |
| --- | --- | --- | --- |
| Qwen3.5-4B Q6_K, исходный контекст | 126.1 с | 143.1 с | JSON/ссылки, но неполная оговорка банка |
| Та же 4B, компактный контекст | 51.9 с | 62.4 с | 324/321 входных токена; оговорка всё ещё пропущена |
| Qwen3.5-9B Q4_K_M, компактный | 80.2 с | Не отправлен | Выигрыш качества не подтверждён; второй запрос пропущен проверка свободной RAM |
| Qwen4B structured-v2 через UI | 73.6 с | 60.2 с | Обязательные поля/ссылки/разные роли; CFO содержал неподтверждённое утверждение о вероятности получения кредитного лимита |
| Qwen4B, вопрос с внедрённой инструкцией | 70.4 с | COO-контекст | Модель отвергла инструкцию; старый валидатор ошибочно отверг саму формулировку отказа |

На одном событии FESCO эти результаты не доказывают качество на всех компаниях, новых новостях или банковской аналитике. Цены и денежная экономия не измерялись. Более крупная модель не показала преимущества, достаточного для дополнительной нагрузки.

Реальные ответы выявили два дефекта проверки: категорическое «повышает вероятность получения кредитного лимита» проходило, а явное опровержение гарантии внутри непроверенного текста ошибочно блокировалось. Для обоих дефектов добавлены отрицательные тесты: они воспроизвели ошибки и прошли после исправления. Текущая политика v3 отправляет старый небезопасный локальный CFO-ответ на проверку: 409 при прямом чтении, скрытие из ленты; payload/snapshot не переписываются. COO-карточка остаётся доступна. Записанный ответ на вопрос перепроверен offline без повторной генерации; исторический failed-результат не подменялся успешным, stop сохранён.

Стенд http://127.0.0.1:8014/ оставлен для просмотра реальных записанных результатов. Новые генерации в нём остановлены после пилота до разбора качества. Приложение сохраняет остановку и не подменяет ответ тестовой моделью. Следующее применение для рассмотрения — подготовка материалов и операционные черновики под проверкой; финансовые выводы требуют отдельного размеченного пилота и независимой приёмки.

## Запуск без Docker

Сначала установите зависимости и соберите frontend по README. Ollama и выбранные веса должны уже присутствовать на сервере. Проверить их можно штатными `ollama list` и read-only `/api/tags`; приложение не выполняет pull.

На Linux-хосте, где Ollama слушает loopback-порту 11434:

```bash
python3 scripts/run_product.py --local-ollama \
  --runtime .tmp/local-product --port 8014 \
  --ollama-url http://127.0.0.1:11434 --auto-refresh
```

В Windows откройте отдельный штатный SSH-туннель к своему настроенному хосту:

```powershell
ssh -N -L 127.0.0.1:11435:127.0.0.1:11434 semenkohome
```

Во втором окне из проекта:

```powershell
.venv/Scripts/python.exe -B scripts/run_product.py --local-ollama --runtime .tmp/local-product --port 8014 --ollama-url http://127.0.0.1:11435 --auto-refresh
```

Модель по умолчанию: `hf.co/unsloth/Qwen3.5-4B-GGUF:Q6_K`. `--local-model` задаётся только оператором из ограниченного списка адаптера. Список включает исследованную 9B, но его качество/ресурсы не приняты для замены 4B. Не используйте `--live`, `--bank`, `--case-csv` или broker-status вместе с локальным режимом. Новый runtime сохраняет историю и stop; смена каталога/runtime для обхода unknown или ошибки не является восстановлением результата.

Проверен запуск без Docker. Обычный Docker-комплект не подключает Ollama автоматически: loopback внутри контейнера отличается от loopback хоста. Контейнерное подключение локальной модели отдельно не принято; публикация Ollama наружу и перенос SSH/API-ключей в образ не требуются этим решением.

## Источники реализации

Используются штатные параметры [Ollama chat API](https://docs.ollama.com/api/chat) и [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), без вызова Ollama Cloud. [Карта 4B](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF) и [карта 9B](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF) указывают Apache-2.0; конкретные веса и их notices оператор проверяет отдельно. Веса в исходный архив проекта не включены, соответствие условиям хакатона из лицензии не следует.
