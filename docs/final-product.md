# Финальный комплект продукта

Пользователь выбирает компанию и роль CFO/COO, видит подтверждённый профиль, запускает анализ событий, открывает карточку с источниками и задаёт уточнение. Интерфейс использует предоставленный дизайн. В публичном каталоге 11 компаний из 11 широких секторов. Четыре обезличенных профиля кейса добавляются отдельным приватным подключением; они не связываются с публичными компаниями.

Готовность частичная. Облачный пилот выявил недостаточное финансовое обоснование ответа CFO и обрезанный JSON в ответе COO. Новые облачные вызовы остановлены. [Результаты пилота](testing.md) и [ограничения](limitations.md) остаются частью комплекта.

Банковский IAM, домен, доступ жюри и ценность на живых новых событиях остаются открытыми. Ниже описан запуск прототипа; команды подключения живой модели не разрешают обход текущего cloud stop.

## Запуск на реальных публичных данных

Нужны Python 3.14, SQLite FTS5 и Docker Compose v2. Из корня проекта в PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r deploy/runtime-requirements.lock
.venv/Scripts/python.exe -B scripts/prepare_product.py --output .tmp/product-demo --port 8089
docker compose -p alpha-product --env-file .tmp/product-demo/product.env -f compose.product.yaml up --build -d --wait
```

Откройте http://127.0.0.1:8089/. При старте и затем раз в час приложение загружает новости из фиксированного набора официальных источников. Пока источники не загружены, анализ недоступен. Ошибки отдельного сайта видны в «Состоянии данных» и не удаляют ранее полученные материалы. Новостная база и история сохраняются в подготовленном runtime после рестарта. Обновление источников не вызывает LLM.

По умолчанию включена **явная тестовая модель**: реальные профили и события проверяют работу приложения, а ответы имеют пометку FAKE MODEL. Для живой генерации необходим отдельно подключённый брокер. Приложение не переключается на fake при ошибке живого запроса.

В Linux/macOS замените `.venv/Scripts/python.exe` на `.venv/bin/python`. Папка подготовки должна быть новой: команда не перезаписывает существующую историю. Остановка без удаления данных:

```powershell
docker compose -p alpha-product --env-file .tmp/product-demo/product.env -f compose.product.yaml stop
```

## Частные материалы и запуск без Docker

Подготовка четырёх профилей и новостей из разрешённых оператору файлов:

```powershell
.venv/Scripts/python.exe -B scripts/prepare_product.py --output .tmp/product-private --case-csv data/raw/clients/df_Uid_data_hack.csv --news-seed .tmp/product-news.sqlite3 --bank-index data/processed/NIGHT-MVP-001/bank/index.sqlite3
docker compose -p alpha-product-private --env-file .tmp/product-private/product.env -f compose.product.yaml -f compose.product.case.yaml -f compose.product.bank.yaml up --build -d --wait
```

`--news-seed` и `--bank-index` необязательны; не передавайте отсутствующие файлы. Без банковского индекса опустите `compose.product.bank.yaml`. Подготовка извлекает только четыре разрешённых профиля в отдельный CSV, проверяет SHA исходного файла и не переносит строки платежей/физических лиц. Исходные материалы и производные индексы отсутствуют в образе и публичном архиве. Предоставляйте их только в разрешённой закрытой среде.

Для запуска интерфейса без Docker нужны Node.js 24 и готовая сборка frontend:

```powershell
npm --prefix frontend ci
npm --prefix frontend run build
.venv/Scripts/python.exe -B scripts/run_product.py --runtime .tmp/product-native --port 8011 --auto-refresh
```

Необязательные `--case-csv` и `--bank` включают разрешённые частные входы. `scripts/update_product_data.py --database PATH --registry data/catalog/news_sources.json` запускает одно ограниченное обновление и печатает только диагностику; это не LLM-вызов. Добавьте `--status` для чтения состояния без сети.

## Живая LLM и закрытый вход

Ключ остаётся в существующем брокере; приложение, Docker и агент не читают credential-файл. Брокер сохраняет шесть разрешённых ID, дневную квоту 4 и предел ответа 512 токенов. Приложение проверяет эти параметры при запуске. При ошибке квоты, доступа, неизвестном исходе или невалидном ответе генерация останавливается без повтора и смены ID. Дневная бюджетная остановка снимается только после естественной смены UTC-дня (03:00 МСК); unknown/auth/invalid требуют разбора оператором и не снимаются снимком квоты.

Linux-хост с уже настроенным брокером может открыть **приватный Unix-сокет**. Запустите следующую команду в отдельном управляемом сеансе оператора; это сервисный процесс, не агент разработки:

```bash
python3 scripts/broker_socket_bridge.py \
  --socket "$PWD/.tmp/product-bridge/broker.sock" \
  --broker-script "$HOME/.local/share/alpha-hack-broker/broker.py"
```

В отдельном несекретном env-файле задайте `PRODUCT_BROKER_RUN_DIR` как абсолютную папку сокета и `PRODUCT_BROKER_GID` как её числовую группу (`id -g`). Добавьте `-f compose.product.live.yaml`. В контейнер попадает только сокет, без SSH-ключей и API-ключа. SIGTERM завершает мост с ожиданием активного запроса и удалением собственного сокета. После аварийного завершения сначала проверьте владельца процесса/сокета; не удаляйте сокет работающего сервиса.

Для закрытой репетиции подготовьте доступ на хосте с OpenSSL:

```bash
python3 scripts/configure_product_access.py --output .tmp/product-access --hostname localhost
```

Команда сохраняет случайный пароль в `operator-access.txt`, хеш для Nginx и отдельные TLS-файлы, печатает только пути. Пользователь читает пароль самостоятельно; ключи, пароль и этот файл не отправляются агентам. Самоподписанный сертификат действует 14 дней и подходит для закрытой репетиции. Для публичного домена оператор заменяет сертификат и ключ на доверенные. Не отключайте проверку TLS в продукте.

Добавьте к Compose `--env-file .tmp/product-access/access.env` и `-f compose.product.https.yaml`. Все бизнес-маршруты за HTTPS требуют Basic Auth, включая POST; записи ограничены по частоте и одновременности. HTTPS привязан к loopback-порту 8443. Для удалённой закрытой проверки используйте разрешённый SSH port-forward; публичный маршрут и сертификат на домен настраиваются отдельным согласованным шагом. Basic Auth защищает демонстрационный стенд, банковский IAM не реализует.

Пример полного запуска на Linux после подготовки приватных входов и несекретного bridge.env:

```bash
docker compose -p alpha-product \
  --env-file .tmp/product-private/product.env \
  --env-file .tmp/product-bridge/bridge.env \
  --env-file .tmp/product-access/access.env \
  -f compose.product.yaml -f compose.product.case.yaml -f compose.product.bank.yaml \
  -f compose.product.live.yaml -f compose.product.https.yaml up --build -d --wait
```

Живой запуск без Docker принимает `--live --broker-status PATH`. Этот файл — безопасный агрегированный ответ штатной команды broker `status`, не credential. `--broker-host` и `--broker-script` задают существующий маршрут; key/endpoint/quota не меняются. Демо следует подключать к одному broker ledger, а не создавать новый бюджет.

## Что подтверждают данные

В `data/catalog/companies.json` у каждого показателя есть период, единицы, периметр и официальный источник. По семи компаниям проверены полугодовые/квартальные раскрытия 2026 года. Годовая выручка 2025 года остаётся отдельной величиной. Порог 15 млрд применяется только к известной годовой выручке группы в рублях. Отгрузки Positive, GMV, квартальная выручка и банковские показатели не подменяют её. Для части компаний сопоставимая выручка не установлена.

## Репетиция перед сдачей

1. Проверьте вход, режим модели и «Состояние данных». Ошибка части источников должна быть видимой; время получения и дата публикации различаются.
2. Выберите FESCO/CFO, раскройте профиль и проверьте источник показателя. Запустите один анализ, откройте карточку и источник новости. Смените роль на COO, сравните задачу и условные выводы.
3. Покажите происхождение фактов, позицию банка из датированного документа и AI-сценарий. «Не найдена» или «не проверялась» — допустимый явный результат; найденный лексический фрагмент не объявляйте актуальным подтверждением.
4. Вопрос-пример заполняет черновик локально. Отправка вопроса — отдельная операция LLM, расходующая общий лимит. Сохраняйте резерв минимум одной из четырёх попыток. При текущем cloud stop живую отправку не выполняйте; API не планирует и не повторяет запросы автоматически.
5. Проверьте мобильную ширину, переключение контекста и сохранение карточки после рестарта. Пустая лента после успешного отбора означает отсутствие подходящих событий в загруженном наборе.

Полезность реальных ответов, полноту источников и независимый GATE оценивают отдельно. Инженерные тесты на fake-модели этого не подтверждают. Перед отправкой владелец проверяет дедлайн, адрес демонстрации и доступ жюри. Публикация этим комплектом не выполняется.
