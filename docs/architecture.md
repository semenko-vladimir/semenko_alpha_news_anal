# Архитектура

Пользователь выбирает компанию и роль, запускает анализ, открывает карточку и проверяет источники. React отвечает за интерфейс. Nginx обслуживает сборку и передаёт `/api` в FastAPI; при разработке запросы проксирует Vite. Backend хранит операции, карточки и диалог в SQLite.

## Данные и запуск

`backend/product_server.py` обслуживает каталог 11 публичных компаний. Оператор может подключить четыре обезличенных профиля кейса. `GET /api/v1/companies/{id}/profile` возвращает показатели и источники, `GET /api/v1/data-status` сообщает об обновлениях и операциях модели. Инструкции находятся в [финальном комплекте](final-product.md).

Сервис загружает новости из разрешённых HTML/RSS-источников при старте и раз в час. Он сохраняет последние успешно полученные материалы при ошибке и не вызывает LLM для обновления. Финансовые показатели оператор обновляет после проверки официальных раскрытий.

## Анализ

`MVPEngine` получает контекст компании, до десяти новостей и до трёх банковских фрагментов на событие. Затем он ранжирует события по роли CFO/COO и передаёт их в `AnalysisPipeline`. Цепочка проверяет формат ответа модели, ссылки, допустимость утверждений о компании и атрибуцию банка. В `mvp_offline` модель тестовая; её ответы обозначены `FAKE MODEL`. Сводка карточки содержит принятый AI-вывод.

Backend получает источники и банковские фрагменты в `prepare`. Последовательность стадий задана кодом; вызов `source_search` через `NoExtraTools` возвращает пустой список `source_ids`. AI пока не планирует шаги и не выбирает инструменты самостоятельно. Критерий 11 на странице 10 кейса остаётся открытым. Режим `agentic_fixture` проверяет ту же основу на фиксированном корпусе, `deterministic_demo` сохраняет прежний компактный пример.

В тестовом режиме цепочка допускает ограниченную коррекцию ошибки валидации. LIVE использует один выбранный материал и один ответ за операцию, без повторного вызова для исправления. Бюджетная ошибка, отказ доступа или неопределённый исход останавливают зависимую генерацию.

## Операции и доступ

`OperationJobs` резервирует устойчивый ID до отправки запроса. `run` хранит fingerprint входов; тот же ключ с прежними параметрами возвращает сохранённый результат, а изменённые параметры дают 409. После неизвестного исхода новый вызов запрещён. Даты, источники, роль, профиль и версия политики входят в контекст. Старые карточки остаются привязаны к своим снимкам данных.

HTTP-клиент не выбирает режим модели, файловые пути или транспорт. Unix-мост вызывает существующий брокер через stdin; только брокер читает API-ключ. Модель получает минимальные признаки компании и ограниченный контекст, без строк платежей и физических лиц. HTTPS/Basic Auth защищает демонстрационный стенд, но не заменяет банковский IAM.

API проверяет компанию, роль, карточку и её снимок для чтения и диалога. Уточнение пользователя становится отдельным источником с пометкой, что сведения не проверены. Оно меняет следующую версию анализа только в своём контексте.

## Источники и объяснение вывода

Факт, позиция банка и AI-сценарий имеют разные типы. Карточка сохраняет ссылки, даты, признаки компании и место фрагмента в документе. Признак отрасли сам по себе не доказывает связь компании с событием. Банковская позиция требует датированного источника; исторический документ не становится текущим мнением. FTS находит совпадения слов и не проверяет смысловую поддержку вывода.

`GET /api/v1/analysis-runs/{run_id}/trace` возвращает разрешённые этапы, статусы и ID источников в проверенном контексте компании, роли и снимка. Промпты, скрытые рассуждения и полный клиентский текст в trace не входят.

Операторская команда `python -m backend.news_service refresh|status --database PATH` отделена от API. `status` читает существующую базу без сети, `refresh` выполняет одно ограниченное получение RSS. Подробности: [команды новостей](../backend/news_service/README.md) и [сценарий показа](judging.md).

## Границы и сопровождение

В Compose входные файлы доступны только для чтения, изменяемые данные хранятся в отдельных volumes, контейнеры работают без root. SQLite рассчитан на локальный прототип. Экспериментальный `local_ollama` использует публичный каталог и серверную модель без ключа брокера; его локальные ID не входят в разрешённый список кейса. Основной маршрут на него не переключается. [Устройство и измерения локального режима](local-llm.md).

Перед подключением источника или расширением профиля нужно назначить владельца, проверить права, происхождение данных, допустимый объём и обработку недоверенного ввода. [Мониторинг качества](quality-monitoring.md) описывает проверки и условия остановки. [Ограничения](limitations.md) перечисляют неподтверждённые возможности.
